# S2-4 预发布验收、校准与回滚手册

本文档对应 `duplicate-s2-4.1`。S2-4 将算法阈值、通道开关和任务快照固定下来，确保一次任务不会因运行中修改环境变量而产生不可复现结果。

## 1. 发布开关

默认采用 fail-closed 配置：

| 配置 | 默认值 | 作用 |
|---|---:|---|
| `DUPLICATE_BATCH_ENABLED` | `false` | 3–10 份文档矩阵模式 |
| `DUPLICATE_SEMANTIC_ENABLED` | `false` | Embedding 语义召回 |
| `DUPLICATE_OCR_ENABLED` | `true` | 本地选择性 OCR |
| `DUPLICATE_REMOTE_OCR_ENABLED` | `false` | 远程 OCR 回退 |
| `DUPLICATE_VISION_ENABLED` | `false` | VLM 图片描述 |
| `DUPLICATE_ALGORITHM_VERSION` | `duplicate-s2-4.1` | 算法/阈值版本 |

阈值通过同名 `DUPLICATE_*` 环境变量覆盖。任务创建时会把开关、阈值、预算写入 `review_tasks.duplicate_feature_snapshot`，执行过程中只读取快照。

## 2. 数据库变更

按顺序执行 `backend/migrations/027...`、`028...`、`029...`、`030...`。生产发布前先在预发布数据库执行并检查：

- `duplicate_document_members`、`duplicate_occurrences`、`duplicate_pair_summaries`、`duplicate_evidence_clusters`
- `review_tasks.duplicate_mode`、`duplicate_algorithm_version`、`duplicate_feature_snapshot`
- 旧 pair 任务仍能从 `/results` 返回；没有 S2-3 索引的历史任务由 matrix API 提供兼容视图。

## 3. 离线校准与压力门槛

候选基准（不调用 LLM）：

```powershell
D:\miniconda3\envs\bjt-agent\python.exe scripts/duplicate_benchmark.py backend/tests/fixtures/duplicate/benchmark_cases.jsonl --top-k 20 --output .artifacts/duplicate-benchmark.json
D:\miniconda3\envs\bjt-agent\python.exe scripts/duplicate_release_gate.py .artifacts/duplicate-benchmark.json
```

基准数据必须按 `text/table/semantic/image/source` 标注；缺少某一类时，release gate 会明确失败，不会把缺失样本当成通过。

10 文档压力测试：

```powershell
D:\miniconda3\envs\bjt-agent\python.exe scripts/duplicate_batch_stress.py --documents 10 --rules 4
```

必须满足：文档对数量为 45、共享证据簇 occurrences 为 10、独立规则流为 4、`n_squared_llm_flows=false`，并记录耗时和峰值内存。

## 4. 预发布双角色验收清单

内部账号和外部账号各执行一遍，使用脱敏的 PDF、DOCX、混合/扫描 PDF：

1. pair 模式上传、解析、启动、取消、超时和重试；关闭 semantic 后重复执行结果可复现。
2. batch 模式上传 3、10 份文档；确认矩阵包含所有文档对，10 份文档不会产生 45 套独立 LLM 流程。
3. 一份文档解析失败时，任务仍能完成其余文档，矩阵和 coverage 明确标记该文档为 `insufficient`。
4. 检查来源文件 hash/version、表格行列证据、图片缩略图、cluster occurrences 和 finding occurrences。
5. 外部账号只能读取自己的项目和结果；内部诊断/执行时间线仍受权限限制。
6. 检查 usage 记录中的 embedding/OCR/vision 调用、缓存命中、失败原因和成本字段。

真实预发布账号、真实业务样本和生产发布审批仍属于外部验收事项；本地自动化测试不能替代这些签字。

## 5. 回滚策略

### 立即止血（不改库）

把 `DUPLICATE_BATCH_ENABLED`、`DUPLICATE_SEMANTIC_ENABLED`、`DUPLICATE_REMOTE_OCR_ENABLED`、`DUPLICATE_VISION_ENABLED` 设为 `false`，滚动重启 duplicate worker。已创建任务继续使用其快照；新任务回到安全的确定性通道。

### 代码回滚

1. 停止接收新的 duplicate 任务，等待 running 任务完成或按页面取消。
2. 回滚应用代码到上一版本，保留 `review_tasks` 的快照字段和 S2-3 表；旧代码不读取这些新增字段也不会影响 pair 结果。
3. 不删除 `duplicate_occurrences`/cluster 数据，便于审计和恢复。

### 数据库回滚

仅在确认没有新版本任务依赖时执行反向 SQL；优先保留表和字段，避免破坏历史结果。若必须回退，先导出四张 S2-3 表和任务快照，再由 DBA 执行经过审核的 `DROP INDEX/ALTER TABLE`，禁止直接删除生产数据。

## 6. 运行中观察

- 任务事件中的 `algorithm_version`、`mode`、`coverage_status` 与数据库快照一致。
- `duplicate_candidates.json` 的 `schema_version`/`algorithm_version` 与任务快照一致。
- batch 候选服务异常时降级为 lexical/structure/image，并把 warning 写入 coverage；不能静默显示“未发现重复”。
