# 2026-07-30 Duplicate check S2-4.2 fixes

This maintenance release resolves the blocking defects found by the real-DOCX
pre-release acceptance run on 2026-07-30.

## Fixes

- Grant the application database role CRUD access to the four S2 batch result
  tables. Migration `034_fix_duplicate_runtime_integrity.sql` supports both
  `ssirs_user` and the legacy `bjt_user` role, and establishes default table
  privileges for future migrations run by the same owner.
- Make all usage-summary counters default to zero at both the database and ORM
  layers. Empty review/blind-check summary inserts now also provide every
  counter explicitly, so zero-provider-call tasks can settle normally.
- Materialize DOCX images through Mammoth before Markdown conversion. Image
  files now reach the SHA-256, perceptual-hash and OCR pipelines instead of
  remaining inline base64 data URIs.
- Exclude image paths, alt text and legacy data-URI placeholders from exact and
  lexical text channels in both pair and batch modes. Image comparison is
  limited to binary/perceptual hashes; OCR text remains eligible as text.
- Decouple semantic recall from `LLM_PROVIDER` through
  `DUPLICATE_SEMANTIC_PROVIDER`. The default `llm` mode performs one bounded,
  task-local semantic-pair recall call with the configured primary LLM. The
  existing MiniMax and Volcengine embedding modes remain available for
  explicitly provisioned endpoints.
- Advance the duplicate runtime snapshot and algorithm identifiers to
  `duplicate-runtime/v2` and `duplicate-s2-4.2`.

## Deployment

1. Back up PostgreSQL and the current application directory after confirming
   that Celery has no active duplicate/review/parser task.
2. Deploy the application while preserving `backend/.env`, `workspace`,
   `Mini-Agent`, RAG build artifacts and dependency directories.
3. Execute `backend/migrations/034_fix_duplicate_runtime_integrity.sql` as the
   migration owner.
4. Restart the backend, review worker and parser worker. Semantic recall runs
   in the review worker.
5. Verify application-role table privileges, usage-summary column defaults,
   service health and queue registration before accepting traffic.

`DUPLICATE_SEMANTIC_ENABLED` remains disabled by default. When enabled without
an explicit provider, `DUPLICATE_SEMANTIC_PROVIDER=llm` is used. Rollback may
restore the prior application directory; migration 034 is backward-compatible
and does not need to be reverted.

## Local verification

- The final duplicate/image/parser/usage regression suite passed with 153 tests
  and 1 intentional skip.
- The broader backend suite reached 557 passes and 3 skips; its remaining
  system/E2E failures require external services, shared databases, MCP or local
  LibreOffice fixtures and are outside this maintenance change.
- Both three-page acceptance DOCX fixtures rendered successfully and were
  inspected page by page. Local parser verification materialized and hashed all
  three images on each side without base64 Markdown residue.

Pre-release deployment and end-to-end acceptance results are recorded in the
workspace test report, not claimed by this implementation note.
