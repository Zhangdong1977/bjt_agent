# 标书生成图表原语库（bidfig）· 原型设计与实施记录

> 2026-10-18。状态：**P0 原型 + P2 渲染自检 + P4 扩类（flow/seq）+ P1 组装机检完成，默认关闭**（`generation_options.fig_mode="bidfig"` 启用），已推 GitHub。
> 动机与方法论来自 2026-10 河南应标项目 hand-src/figlib 图源体系：**LLM 只填数据，版式由确定性代码负责**。

## 1. 背景与问题

现行标书生成的图表 = LLM 直书 mermaid 源码 → 前端 chartAssets 渲染 PNG。真机实绩：
- 反馈⑨（09-03）：21 图仅约 7 成可渲染（`<br>` 未自闭合致 SVG 非良构、漏闭合围栏级联错配）；
- 反馈⑩（09-07）：甘特图短跨度按日出刻度挤叠、title 被画布裁剪、开标一览表写入丢失；
- chartAssets 里已堆了 6+ 个 mermaid 黑盒补丁（width:100%、DOMPurify 剥 foreignObject、topAxis 去底轴、tickInterval 注入、gantt 标头自绘…），每个补丁都在跟渲染器搏斗，且同类问题会在每张图重复出现。

## 2. 范式

| 环节 | 现行 | bidfig |
|---|---|---|
| LLM 输出 | mermaid 源码（文本） | 结构化 JSON（`kind=gantt/arch`） |
| 版式/良构性 | mermaid 黑盒 + 前端补丁 | 服务端纯 Python 拼 SVG，代码保证 |
| 服务端依赖 | 无（渲染在前端） | **无新增**（纯文本拼接，无 cairo/node） |
| 前端 | mermaid.render → PNG | SVG 直接光栅化 → 同一 `bjt-chart://N` 通道 |
| 版式修复成本 | 改 prompt/补丁，逐图复发 | 改原语一处，全体图表受益 |
| 数据级返修 | 重新生成整节文字 | 改 JSON 重渲，零 LLM 调用 |

单一真源：section md 落盘保存 ```bidfig JSON（可 diff、可重渲）；API 出口（`/sections/{node_id}`、`/assembled`）调用 `render_bidfig_fences` 即时转换为 ```bidfig-svg 围栏，前端按"已渲染 SVG"光栅化。

## 4. JSON Schema（prompt 内模板即权威）

```json
{"kind":"arch","title":"图题",
 "layers":[{"name":"层名","modules":[{"name":"模块名","sub":["要点1","要点2"]}]}],
 "side":[{"name":"保障体系","items":["要点"]}]}          // side≤3，可省略
{"kind":"gantt","title":"图题",
 "phases":[{"name":"阶段名"}],                            // 可省略
 "tasks":[{"name":"任务名","phase":0,"start":"2026-11-01","end":"2026-12-10"}],
 "milestones":[{"name":"M1","date":"2026-12-10"}]}        // 可省略；tasks/milestones 至少一项
{"kind":"flow","title":"图题",                             // P4：阶段=列，1-5 列
 "phases":[{"name":"阶段名","steps":[{"name":"步骤名","note":"要点（可省略）"}]}]}
{"kind":"flow","title":"图题",                             // P4：无阶段单列线性
 "steps":[{"name":"步骤名","note":"要点"}]}
{"kind":"seq","title":"图题",                              // P4：参与方 2-6
 "actors":["参与方A","参与方B"],
 "messages":[{"from":0,"to":1,"text":"消息说明","dash":false}]}  // from/to=actors 下标，dash=虚线返回
```

校验（`BidfigSpecError` 聚合报错）：日期 YYYY-MM-DD、end≥start、phase 下标或名称可解析、名称非空、side≤3、modules 每层≥1、flow 阶段≤5/每阶段步骤≤12、seq 参与方 2-6/消息≤20/下标可数字字符串。渲染失败 → 段内降级为"（图表数据无效，已省略）"+ warning 日志，**不阻断整节**；渲染成功再过 **P2 几何自检**（`svg_bounds_issues`：text 估宽×1.08、rect/line 越界），越界时 `tightened(0.92)` 收紧重渲一次（折行/截断宽度整体 -8%，同数据确定性重渲=版式级自动修复），仍越界保留原稿记 error。

## 5. 开关与兼容性

- **默认关**：`BidDraftOptions.fig_mode` 不传（或传 mermaid）时 system prompt、落盘、API 输出与现状完全一致（有测试守卫：`test_agent_prompt_fig_mode_default_off`）。
- 桥协议 / VSTO / Word 写入路径**零改动**（仍走 `bjt.vsto.insert` 的 `images` PNG 通道）。
- 旧任务的 mermaid 块继续走原管线；bidfig 与 mermaid 可在同节共存（各自 clamp 上限 2）。
- 开启方式：`POST /api/bid-draft/tasks` 的 `options: {"fig_mode":"bidfig"}`（暂无 UI 开关）。

## 7. 已知限制与后续路线

限制：占比/饼图等仍走 mermaid；LLM 出坏 JSON 只降级未自动重试；数据级重渲无独立 API；P2 自检是纯估算几何检查（非像素级光栅验证——零依赖约束下的务实取舍，真字体偏差靠 ×1.08 安全余量 + 收紧重渲兜底）。

后续（按此前 P0-P4 规划）：
- ~~P1 组装期全文档机检挂 assemble 阶段~~ **已落地**（`bid_doc_checks.py`：围栏配平/空章节/重复标题/模板残留/术语口径 → summary.doc_checks，只报告不改写）；
- ~~P2 图渲染自动像素自验~~ **已落地**（`svg_bounds_issues` 几何自检 + `tightened(0.92)` 自动收紧重渲一次，见 §4）；
- P3 素材注入与证据锚点（把"严禁虚构"机制化）——**未做**，涉及素材上传/引用协议的产品决策；
- P4 原语扩类：**flow/seq 已落地**；拓扑图未做（分层拓扑可先由 arch 覆盖）；单源多目标输出（暗标/模板版式变换）未做。

方法论纪律（自应标 20 图修复沉淀）：**系统性缺陷修在原语，个例缺陷才修实例；任何返修后全量复验**（局部修复常在邻域引入回归）。本轮 P4 验证再次印证：visual-judge 首轮 2/5（flow 要点单行硬截断、seq 自交互回环顶线压字）→ 两处均为原语级修复 → 全量复验 5/5。
