# 标书生成图表原语库（bidfig）· 原型设计与实施记录

> 2026-10-18。状态：**原型完成，默认关闭**（`generation_options.fig_mode="bidfig"` 启用），未提交、未发版。
> 动机与方法论来自 2026-10 河南应标项目 hand-src/figlib 图源体系：**LLM 只填数据，版式由确定性代码负责**。

## 1. 背景与问题

现行标书生成的图表 = LLM 直书 mermaid 源码 → 前端 chartAssets 渲染 PNG。真机实绩：
- 反馈⑨（09-03）：21 图仅约 7 成可渲染（`<br>` 未自闭合致 SVG 非良构、漏闭合围栏级联错配）；
- 反馈⑩（09-07）：甘特图短跨度按日出刻度挤叠、title 被画布裁剪、开标一览表写入丢失；
- chartAssets 里已堆了 6+ 个 mermaid 黑盒补丁（width:100%、DOMPurify 剥 foreignObject、topAxis 去底轴、tickInterval 注入、gantt 标头自绘…），每个补丁都在跟渲染器搏斗，且同类问题会在每张图重复出现。

## 2. 范式

| 环节 | 现行 | bidfig |
|---|---|---|
| LLM 输出 | mermaid 源码（文本） | 结构化 JSON（`kind=gantt/arch`） |
| 版式/良构性 | mermaid 黑盒 + 前端补丁 | 服务端纯 Python 拼 SVG，代码保证 |
| 服务端依赖 | 无（渲染在前端） | **无新增**（纯文本拼接，无 cairo/node） |
| 前端 | mermaid.render → PNG | SVG 直接光栅化 → 同一 `bjt-chart://N` 通道 |
| 版式修复成本 | 改 prompt/补丁，逐图复发 | 改原语一处，全体图表受益 |
| 数据级返修 | 重新生成整节文字 | 改 JSON 重渲，零 LLM 调用 |

单一真源：section md 落盘保存 ```bidfig JSON（可 diff、可重渲）；API 出口（`/sections/{node_id}`、`/assembled`）调用 `render_bidfig_fences` 即时转换为 ```bidfig-svg 围栏，前端按"已渲染 SVG"光栅化。

## 4. JSON Schema（prompt 内模板即权威）

```json
{"kind":"arch","title":"图题",
 "layers":[{"name":"层名","modules":[{"name":"模块名","sub":["要点1","要点2"]}]}],
 "side":[{"name":"保障体系","items":["要点"]}]}          // side≤3，可省略
{"kind":"gantt","title":"图题",
 "phases":[{"name":"阶段名"}],                            // 可省略
 "tasks":[{"name":"任务名","phase":0,"start":"2026-11-01","end":"2026-12-10"}],
 "milestones":[{"name":"M1","date":"2026-12-10"}]}        // 可省略；tasks/milestones 至少一项
```

校验（`BidfigSpecError` 聚合报错）：日期 YYYY-MM-DD、end≥start、phase 下标或名称可解析、名称非空、side≤3、modules 每层≥1。渲染失败 → 段内降级为"（图表数据无效，已省略）"+ warning 日志，**不阻断整节**。

## 5. 开关与兼容性

- **默认关**：不传 `fig_mode` 时 system prompt、落盘、API 输出与现状完全一致（有测试守卫：`test_agent_prompt_fig_mode_default_off`）。
- 桥协议 / VSTO / Word 写入路径**零改动**（仍走 `bjt.vsto.insert` 的 `images` PNG 通道）。
- 旧任务的 mermaid 块继续走原管线；bidfig 与 mermaid 可在同节共存（各自 clamp 上限 2）。
- 开启方式：创建任务时 `generation_options: {"fig_mode":"bidfig"}`（API 层暂未暴露 UI 开关，走接口直传）。

## 6. 验证结果

- pytest：`test_bidfig` 14/14 + `test_bid_generation` 回归全绿（共 27）。
- 前端 `npm run build` 通过（仅既有 chunk 体积警告）。
- **视觉评审两轮 A/B**（`scripts/demo-out/bidfig-compare.png`，同题对比：150 天横道图 / 4 层架构图 / 8 天短跨度）：
  - 第一轮抓出 bidfig 右端收边缺陷（末端菱形越框 ~5px）→ 原语加 3% 轴内边距一处修复，两案例同时生效；
  - 第二轮 **bidfig 3/3 判"可直接插入标书的可用水平"**；mermaid 3/3 判不可用（结构性缺陷：里程碑全部错并进末阶段、首月无刻度、today 红线杂线、短跨度日刻度逐条重复、架构图被拉成整页竖长条且侧栏失去贯通语义）。
- 确定性：同 spec 逐字节复现（测试断言）；良构性：xml.etree 严格解析（测试断言）。

## 7. 已知限制与后续路线

限制：仅 gantt/arch 两类（流程/时序/占比仍走 mermaid）；无 UI 开关；LLM 出坏 JSON 只降级未自动重试；数据级重渲无独立 API。

后续（按此前 P0-P4 规划）：
- P1 组装期全文档机检（编号/交叉引用/术语口径/敏感词 regex——可复用应标机检脚本方法论）挂 assemble 阶段；
- P2 图渲染自动像素自验（渲染后扫溢出/压线，失败自动重试一次）；
- P3 素材注入与证据锚点（把"严禁虚构"机制化）；
- P4 原语扩类（流程图/时序图/拓扑图）与单源多目标输出（暗标/模板版式变换）。

方法论纪律（自应标 20 图修复沉淀）：**系统性缺陷修在原语，个例缺陷才修实例；任何返修后全量复验**（局部修复常在邻域引入回归）。
