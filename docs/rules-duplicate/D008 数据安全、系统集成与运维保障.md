# D008 数据安全、系统集成与运维保障

## 检查目标

检查数据安全、网络与应用安全、系统集成、部署容灾、监控告警和运维保障中的自主设计，识别接口名、阈值、拓扑和内部流程的异常一致。结果只用于人工复核，不作串标、围标或其他法律定性。

## 适用证据与检索通道

- 以安全方案、数据分级表、权限矩阵、接口清单、部署拓扑说明、备份计划、监控指标和运维流程为证据。
- lexical 比对接口、端口、账号角色、阈值和内部名；structure 比对权限/接口/巡检表；semantic 比对安全与运维逻辑；image 检查拓扑图、截图和 OCR。
- 等保、密码、数据保护等标准或法规要求必须有固化 tender/public 来源，不能由模型记忆确认。

## 检查项

### 检查项1：数据分类分级、存储和生命周期

- 比对数据类别、敏感级别、保存期限、脱敏、归档、销毁和跨域流转规则。
- 相同非公开字段名、分级例外、保留天数和处理顺序属于增强证据。

### 检查项2：身份认证、权限和审计

- 比对账号体系、双因素认证、角色矩阵、最小权限、审批链、审计字段和留存期限。
- 通用安全原则不充分；相同内部角色名、权限缺口、日志字段和异常阈值应重点复核。

### 检查项3：网络、应用和数据安全控制

- 比对网络分区、防护设备、加密算法、密钥管理、接口签名、漏洞处置和安全测试步骤。
- 标准算法名称可合理重复；自定义策略名、端口组合、密钥轮换周期和同一错误配置属于高价值线索。

### 检查项4：系统集成、接口和协议

- 比对关联系统、接口路径、协议、字段映射、调用频率、超时重试、幂等和异常码。
- 相同内部系统名、API 路径、字段拼写错误、测试地址或非强制性能数字同时出现时提高风险。

### 检查项5：部署、高可用和灾备

- 比对节点角色、主备/集群、负载均衡、RPO/RTO、备份频次、切换条件和恢复演练。
- 标准高可用术语不足以单独判定；相同节点命名、端口、脚本、阈值和故障顺序构成组合证据。

### 检查项6：性能、监控和告警

- 比对吞吐、并发、响应时间、资源阈值、监控指标、告警级别、通知对象和抑制规则。
- 招标未规定的多个阈值、仪表盘名、告警表达式和联系人尾号一致时应重点标记。

### 检查项7：运维巡检、变更和事件管理

- 比对巡检周期、工单字段、变更审批、发布窗口、故障升级、复盘和知识库流程。
- 相同内部平台名、脚本路径、班次、应急口令或复制残留公司名属于增强证据。

## 合理重复

- 招标文件明确的安全等级、接口规范、RPO/RTO、性能指标和运维服务要求。
- 法规、国家/行业标准固定术语及公共产品的标准配置说明；需有可追溯来源。
- “最小权限、定期备份、监控告警”等通用原则不单独判定疑似重复。

## 疑似不合理重复

- 内部接口路径、字段错误、端口、账号角色、告警阈值、脚本路径和恢复顺序同时一致。
- 非强制的数据分级规则、权限矩阵、巡检表和灾备操作逐项一致。
- 拓扑图 OCR、正文和表格共同残留另一方系统名、域名、IP、公司或项目代号。

## 排除与降级

- 标准安全口号、算法名称、公共协议字段和低证据短语降级。
- 拓扑 OCR 不完整、接口上下文缺失、来源版本不明或证据强度不足时标记 unknown。
- 证据不足时不得断言违反安全法规、泄露数据或存在协同行为，不得自行补全 IP、账号和接口事实。

## 输出要求

- 引用双方原文/表格/图片位置、接口和阈值、匹配通道、相似度、证据强度及来源快照。
- 明确指出公共标准与内部设计的边界，并给出删除敏感残留、改写或人工核验建议。
- verdict 只能为 reasonable、suspicious 或 unknown；不得作出确定性的违法结论。
